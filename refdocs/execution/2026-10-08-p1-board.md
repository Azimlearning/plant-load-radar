### Task 1 — Planner core — ✅ DONE 2026-10-08

> `src/core/planner.ts` (12 tests). `prebuildAlternative` shifts quiet-week production into the target week and re-runs `decide`, so there is no second rule. Found and fixed negative zero in `residualShortM3`.

**Files:** `src/core/planner.ts`, `src/core/planner.test.ts`.

1. `weekBalances(weeks, requestsByWeek)` → per week `{ week, capacityM3, committedM3, freeM3, requestedM3, spareM3 }` where `spareM3 = freeM3 − requestedM3` (negative = short). Pure.
2. `recommend(weeks, requests, opts)` → for each contested week of `decide()`: the served and deferred entries with ringgit, and where each deferred request lands (week or unplaced), plus `shortM3`.
3. `prebuildAlternative(weeks, requests, stockCapM3, targetWeek)` → `planPrebuild` over the balances before the target week, then re-run `decide` with the moved volume (earlier weeks' committed + the moved m³, the target week's capacity + the moved m³). Return `{ moves, coveredM3, residualShortM3, outcomeWithPrebuild }`.
4. No new maths beyond sums and differences; reuse `decide`, `planPrebuild`.

**Verify:** `npm test -- planner` — (a) on a hand-built three-week fixture the balances are exact; (b) the week-43-style fixture gives A served, B moved, ringgit equal to `slipCostRM`/`contributionMarginRM`; (c) pre-build with a cap of 0 changes nothing and with a large cap covers the shortage; (d) a cap that covers part of the shortage reduces `residualShortM3` by exactly that part; (e) pre-build never uses spare from a week *after* the target.
